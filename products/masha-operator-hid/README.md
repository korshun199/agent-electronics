# Masha Operator HID

Стендовый мост для управления USB-host устройством: полётник HAKRCF405V2 на STM32F405 принимает ограниченные команды по UART4 и выдаёт USB HID-клавиатуру. Отдельный видеоконвертер показывает выход цели на ноутбуке. Это прототип для локальной работы без сетевого доступа к цели.

## Что входит

- `firmware/HAKRCF405V2_MashaOperatorHID.hex` — клавиатурный образ.
- `host/operator_uart.py` — отправитель ограниченных клавиатурных событий по UART.
- `source/` — патчи Betaflight и скрипт их применения.
- `tools/verify_firmware.py` — проверка Intel HEX.
- `mouse/` — дополнительная сборка с относительной USB-мышью; её движение ещё не подтверждено на экране.
- `SHA256SUMS` — контрольные суммы клавиатурного набора.

Лицензия и исходный upstream указаны в [`LICENSE`](LICENSE) и патчах. Публикуются воспроизводимые исходники и образы, но не локальный полный дамп полётника или журнал его прошивки.

## Подключение проверенного стенда

```text
Raspberry Pi 4 USB-host  <── USB ──>  HAKRCF405V2 (USB HID keyboard)
                                         │ UART4
Ноутбук USB <── YP-05 / FT232RL ─────────┘
Ноутбук USB <── EasierCAP / UVC capture <── видеовыход Raspberry Pi
```

Для управляющего UART: FT232 TXD → RX4 (PA1), FT232 RXD ← TX4 (PA0), GND ↔ GND. Уровни UART — 3,3 В. VCC между платами не соединять. Полётник подключается своим USB к USB-host цели; FT232 остаётся на ноутбуке как управляющий канал. Видеоконвертер — отдельный путь, его `/dev/videoN` определяется заново при каждом подключении.

Если одновременно видны FT232 и UVC-захват, это ожидаемая сторона ноутбука. Наличие или отсутствие самого полётника в USB-списке ноутбука зависит от его физического USB-подключения; не считать это доказательством HID-ввода на цели.

## Команды и сборка

Клавиатурный UART: 115200, 8N1. Кадр клавиши — `A5 modifier usage checksum`, checksum — XOR первых трёх байтов. Прошивка отправляет press и release с паузами, затем отвечает `ACK`; `ERR` означает некорректную команду, `ARM` — блокировку при armed-состоянии. ACK подтверждает обработку кадра контроллером, а не реакцию целевого приложения.

```bash
python3 -m pip install pyserial
python3 host/operator_uart.py --help
sha256sum -c SHA256SUMS
python3 tools/verify_firmware.py firmware/HAKRCF405V2_MashaOperatorHID.hex
```

Сборка выполняется на чистом Betaflight 4.5.4 commit `25356b59a96dc975d777844f896b7c7855ea90e6`, с config submodule `8057d261bb43a706764f73928b919af62666c247`:

```bash
git clone --branch 4.5.4 --recurse-submodules https://github.com/betaflight/betaflight.git betaflight-4.5.4
cd betaflight-4.5.4
git checkout 25356b59a96dc975d777844f896b7c7855ea90e6
git submodule update --init -- src/config
/path/to/agent-electronics/products/masha-operator-hid/source/apply_patch.sh "$PWD"
GCC_REQUIRED_VERSION=13.2.1 make -j2 CONFIG=HAKRCF405V2
```

Для мышиной сборки см. [`mouse/README.md`](mouse/README.md). Сборка и HEX-проверка сами по себе не подтверждают запись, загрузку или работу на целевом USB-host.

## Проверенный результат на стенде

26 ноября 2026 года на Raspberry Pi 4 показан свежий видеокадр через подключённый USB-видеозахват. После исправления физического подключения контроллер получил UART-команды с ACK; целевой экран показал ввод тестового значения в поле пароля, а после Enter — штатный отказ `Incorrect password, please try again.` Это подтверждает end-to-end клавиатурный ввод и отправку формы на этой конфигурации. Данные учётной записи и тестовая строка в репозитории не сохраняются.

Видеозахват ноутбука наблюдался как EasierCAP/AV-to-USB2.0, UVC/MJPEG 720×480 при 25 кадрах/с (устройство в Linux получило временное имя `/dev/video4`). Для читаемого обзора применялись crop 460×260 с началом (130,100), небольшая коррекция контраста и увеличение до 1380×780. Имена `/dev/videoN` непостоянны; часть захваченных MJPEG-кадров содержала артефакты. Это локальный просмотр, не интеграция изображения в текущий интерфейс агента.

### Уровни проверки

| Возможность | Состояние |
| --- | --- |
| Клавиатурный HEX, исходники и контрольные суммы | Проверены локально |
| Flash клавиатурной версии и полный readback | Проверены в аппаратном сеансе; устройство-специфические дампы не публикуются |
| UART ACK и видимый ввод на Raspberry Pi | Подтверждены свежим кадром |
| Отправка формы и ожидаемый отказ входа | Подтверждены свежим кадром |
| Захват и локальный показ видеовыхода | Проверены вручную на этом конвертере |
| Мышиный HEX, запись и readback | Подтверждены; устройство перечисляло HID-отчёт с отдельным ID мыши |
| Видимое движение/клик мыши после правильной перекоммутации | Не подтверждены |
| MCP/agent-native захват кадров и управление | Не реализованы |

## Ограничения

- Это не универсальная совместимость: подтверждена конкретная связка HAKRCF405V2 и Raspberry Pi 4.
- Мышь остаётся экспериментальной до проверки движения и кнопок на свежем видеокадре.
- Видеопоказ сейчас выполняется отдельно локальным просмотрщиком; автоматическая блокировка HID по устаревшему кадру не реализована.
- Прошивка заменяет Betaflight на полётнике и не предназначена для полёта. Не подключать моторы/пропеллеры во время стендового использования.
- Не включать в Git резервные копии Flash, серийные номера, пользовательские кадры, журналы аппаратных операций и сведения учётных записей.
