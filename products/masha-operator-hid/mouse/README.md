# Мышь для Masha Operator HID — экспериментальная версия

Эта отдельная версия прошивки добавляет USB relative mouse к UART4-клавиатуре. В одном HID-интерфейсе используются Report ID 1 для клавиатуры и Report ID 2 для мыши; классический boot protocol отключён, интерфейс работает по report descriptor. UART4 принимает два ограниченных типа кадра. Образ записан в контроллер и полностью проверен чтением Flash назад. В правильной стендовой схеме клавиатурный ввод и отправка формы подтверждены на Raspberry Pi 4; движение и клики мыши после этой прошивки на экране ещё не подтверждены.

## Файлы

- `firmware/HAKRCF405V2_MashaOperatorHID_mouse.hex` — записанный экспериментальный образ; содержимое проверено чтением Flash назад.
- `source/` — воспроизводимые патчи к закреплённым версиям Betaflight и скрипт их применения.
- Device-specific запись и полный readback выполнены в аппаратном сеансе. Локальный скрипт, журнал и резервная копия намеренно не публикуются. Для повторной записи или reset требуется отдельное согласование.
- `host/operator_mouse.py` — отправка одного относительного движения, колеса или короткого клика.
- `../firmware/HAKRCF405V2_MashaOperatorHID.hex` и `../host/operator_uart.py` — предыдущий проверенный клавиатурный вариант и отправитель.
- `SHA256SUMS` — контрольные суммы артефактов этого варианта.
- `../LICENSE` — лицензия Betaflight GPL-3.0.

## Команды мыши

UART: 115200, 8N1. Кадр мыши — шесть байтов:

```text
A6 buttons dx dy wheel checksum
```

`checksum` — XOR предыдущих пяти байтов. `buttons`: bit 0 — левая, bit 1 — правая, bit 2 — средняя кнопка. Смещения `dx`, `dy` и `wheel` знаковые в диапазоне -127..127. После каждого отчёта полётник через 30 мс передаёт нейтральный отчёт (отпускает кнопки), ещё через 30 мс отвечает `ACK`. Значение за пределами диапазона, неизвестные флаги и пустая команда отклоняются `ERR`; при armed-состоянии возвращается `ARM`.

Примеры:

```bash
python3 -m pip install pyserial
python3 host/operator_mouse.py --port /dev/ttyUSB0 --dx 24 --dy -10
python3 host/operator_mouse.py --port /dev/ttyUSB0 --wheel 1
python3 host/operator_mouse.py --port /dev/ttyUSB0 --button left
```

Смещения относительные, не координаты экрана; направление Y и чувствительность определяет хост. Один запуск отправляет ровно одно ограниченное событие. Сначала проверять в пустом безопасном поле, без нажатий, способных подтвердить покупку, удалить данные или изменить настройки.

Клавиатурная команда остаётся прежней: `A5 modifier usage XOR` и используется `../host/operator_uart.py`.

## Сборка

Используй чистый Betaflight 4.5.4 commit `25356b59a96dc975d777844f896b7c7855ea90e6` и config-submodule commit `8057d261bb43a706764f73928b919af62666c247`:

```bash
git clone --branch 4.5.4 --recurse-submodules https://github.com/betaflight/betaflight.git betaflight-4.5.4
cd betaflight-4.5.4
git checkout 25356b59a96dc975d777844f896b7c7855ea90e6
git submodule update --init -- src/config
/path/to/agent-electronics/products/masha-operator-hid/mouse/source/apply_patch.sh "$PWD"
GCC_REQUIRED_VERSION=13.2.1 make -j2 CONFIG=HAKRCF405V2
```

Скрипт проверяет upstream commit-ы и чистоту дерева, затем применяет полный комплект keyboard+mouse. Он не записывает устройство. HEX здесь собран локально тем же GCC 13.2.1. В штатном Betaflight по умолчанию ожидается GCC 10.3.1.

Проверить комплект можно командами из каталога `mouse/`:

```bash
sha256sum -c SHA256SUMS
python3 ../tools/verify_firmware.py firmware/HAKRCF405V2_MashaOperatorHID_mouse.hex
```

## Статус и границы

Проверено: сборка завершилась; report descriptor содержит две коллекции и раздельные Report ID; HEX прошёл проверку формата и адресов; запись завершена, все 521435 байт образа, затронутая область Flash и нетронутый хвост совпали при readback. Клавиатурный ввод и отправка формы подтверждены свежим кадром на Raspberry Pi 4. Не проверено: видимое движение указателя, клики и совместная работа мыши с целью.

Контроллер — полётник, новая прошивка заменяет Betaflight и для полёта не подходит. Дамп Flash и любые новые записи требуют отдельного согласования. Для незавершённой runtime-проверки мыши потребуется заново определить состояние платы и подключение, затем получить отдельное согласование на reset/запуск. Не использовать моторы и пропеллеры.
