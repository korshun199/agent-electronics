# Веста — восстановление Raspberry Pi

## Результат

Исследована загрузка Raspberry Pi с зашифрованным корневым разделом. По сохранённому загрузочному окружению установлено использование LUKS2 и программы `get-key` для получения данных разблокировки через UART.

Пассивная двусторонняя запись штатной загрузки позволила проверить корректность кадров и подлинность ответа. Полученный результат принят LUKS на копии раздела. Отдельная рабочая копия открыта только для чтения, а её файловая система сохранена в незашифрованном виде и сверена. Физическая исходная карта не переписывалась.

## Архитектура

Штатный источник питания подаётся на плату расширения, от которой питается Raspberry Pi. После запуска ядра initramfs получает данные разблокировки, затем загружается Debian 12. Служба systemd создаёт временную копию прикладного каталога и запускает основной исполняемый файл. В прикладном каталоге обнаружены конфигурация, вспомогательные сценарии и библиотеки обработки видео.

Эта инвентаризация не подтверждает назначение каждого аппаратного вывода, полную внутреннюю логику бинарной программы или криптографическую проверку подписей загрузчика.

## Границы публикации

Ключи, содержимое UART, образы, копии файловой системы, персональные конфигурации и специфические для устройства локальные пути в репозиторий не включены. Локальные отчёты и скрипты восстановления остаются на рабочем компьютере. Эксперименты на копиях не заменяют проверку аппаратуры и не оправдывают изменение защиты или прошивки.
