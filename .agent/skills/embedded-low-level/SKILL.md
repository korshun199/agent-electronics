# Низкоуровневая разработка микроконтроллеров

Используй навык, когда нужно понять или реализовать путь от reset до конкретного аппаратного события без предположения, что HAL или RTOS скрывают важные детали. Сначала определи точный MCU, корпус, ревизию платы, компилятор, linker script, SDK и режим загрузки.

## Установи аппаратный и программный контекст

- Определи точную маркировку микроконтроллера, семейство ядра, адресное пространство и доступную память по документации производителя.
- Различай данные из datasheet, reference manual, errata, board schematic, BSP и фактических измерений. Для регистра используй reference manual/официальный header именно данного MCU.
- Найди фактические startup-файлы, linker script, таблицу векторов, настройки тактирования, сборочные флаги и версию toolchain. Не подменяй эту картину настройками похожего проекта.
- До изменения зафиксируй исходное состояние и проверь, какие участки кода или linker configuration принадлежат SDK или генератору.

## Проследи загрузку и память

Понимай и проверяй цепочку: reset/boot ROM → выбор образа → таблица векторов → reset handler → копирование `.data` → очистка `.bss` → инициализация тактирования/памяти → C/C++ runtime → `main` или RTOS scheduler.

- Сверь начальный stack pointer, адрес reset handler, выравнивание векторов и допустимые регионы памяти.
- Проверяй map-файл, ELF sections, символы, размер стека/heap, размещение DMA-буферов, retention/RTC memory и внешней RAM.
- Различай адрес загрузки, исполнения и хранения; отдельно проверяй секции копирования/zero-init и загрузочные таблицы.
- Для C++ проверь порядок статических конструкторов, таблицы init/fini и требуемую поддержку исключений/RTTI, если они включены.
- Не меняй linker script, boot configuration, option bytes или layout flash без отдельной задачи и проверки совместимости с bootloader/partition table.

## Работай с регистрами и периферией

- Перед настройкой периферии проследи clock/reset gate, mux пина, режим ввода/вывода, электрические ограничения и все связанные регистры.
- Используй маски и именованные поля вместо магических констант. Проверь ширину регистра, допустимые значения, зарезервированные биты и последовательность записи.
- Учитывай семантику регистров: write-one-to-clear, read-to-clear, set/clear aliases, shadow registers, FIFO, latched status и write protection.
- Не делай read-modify-write для регистра, где чтение или запись имеет побочные эффекты. Предпочитай документированные atomic set/clear регистры.
- Для GPIO разделяй логическое состояние и электрическое: active-high/low, open-drain/push-pull, pull-up/down, drive strength, slew rate и состояние при reset.
- Проверь, кто ещё владеет пином или периферией: boot strap, debugger, другой драйвер, DMA, RTOS или второй core.

## Прерывания, DMA и конкурентность

- Для каждого ISR укажи источник, приоритет, способ подтверждения/сброса флага, худшее время выполнения и взаимодействие с остальным кодом.
- Держи ISR коротким и ограниченным по времени; переносить тяжёлую обработку в task/main loop, если это допускают задержки.
- `volatile` не является блокировкой и не гарантирует атомарность, порядок между ядрами или очистку кэша. Используй атомарные операции/критические секции согласно ядру и RTOS.
- Для DMA проверь выравнивание и допустимость области памяти, направление, длину, инкремент адреса, cache coherency, барьеры памяти, ownership буфера и момент завершения.
- В циклических буферах формально проверь wrap-around, гонку producer/consumer, переполнение, потерю данных и тайм-аут восстановления.
- Измеряй латентность, jitter и пропускную способность на целевом устройстве; не выводи их из частоты CPU или сборки.

## Периферийные драйверы и тайминг

- Для таймеров выведи частоту счётчика из реальных источников clock и prescaler; проверь переполнение, capture/compare, PWM полярность, dead-time и синхронизацию каналов.
- Для UART проверь источник baud clock, oversampling, word length, parity, stop bits, FIFO/ошибки и границы кадра.
- Для SPI зафиксируй CPOL/CPHA, порядок бит, chip-select timing, максимальную частоту, трёхстороннее состояние MISO и длину транзакции.
- Для I²C учти open-drain, pull-up и ёмкость шины, адресный формат, clock stretching, repeated start, arbitration и bus recovery.
- Для ADC проверь опору, время выборки, входное сопротивление, trigger, последовательность каналов, калибровку и переходы аналоговых/цифровых доменов.
- Для watchdog определи, какие зависания он должен обнаруживать, когда и кем обслуживается, что сохраняется при reset и как избежать обслуживания из неисправной петли.

## C/C++ и воспроизводимая сборка

- Выбирай типы фиксированной ширины (`uint32_t` и т.п.), явные преобразования и проверку переполнений; не предполагай размер `int`, endian или ABI.
- Избегай неопределённого поведения, гонок, unaligned доступов и строгого aliasing нарушений. Для MMIO применяй определения/примитивы, предусмотренные toolchain и MCU SDK.
- Для фиксированной арифметики документируй масштаб, единицы, округление и насыщение. Не позволяй signed overflow и переполнению промежуточных результатов оставаться неявными.
- Проверяй compiler flags, оптимизацию, LTO, ABI, startup-объекты, библиотеки и версию SDK. При неожиданном поведении изучи disassembly и map, а не только исходник.
- Делай host-тесты парсеров и чистой логики, статические проверки, сборку и анализ ELF отдельно. Ни один из них не является доказательством работы на физическом MCU.

## Отладка и подтверждение

Иди от наблюдаемого симптома к сигналу: питание/reset/clock → boot → PC/stack/vector → периферийные регистры → линии осциллографом/логическим анализатором → данные/протокол → прикладная функция.

- Сохраняй исходный лог/образ и меняй за раз один фактор.
- Используй SWD/JTAG и trace с учётом влияния остановки ядра; debug halt может менять тайминги и периферийное состояние.
- Проверяй fault registers, stack frame, map ELF, watchpoints и аппаратные event counters, если доступны.
- Сравнивай настроенные параметры с фактическими сигналами измерительного прибора. Уровень пина подтверждай только безопасным способом и в пределах входного диапазона прибора.
- В отчёте отдельно перечисляй код собран, код записан, MCU соединился, firmware загрузилась и функция измерена. Подтверждённым считается только то, что действительно наблюдалось.

## Безопасность

Не подавай питание и внешние сигналы без подтверждённых напряжений, распиновки, общей земли/изоляции и ограничения тока. Не прошивай, не стирай память и не меняй boot/option bytes без отдельного разрешения; перед разрешённой записью идентифицируй MCU, сохрани проверенную копию и определи способ отката.
