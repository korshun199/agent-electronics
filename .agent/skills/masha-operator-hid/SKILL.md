# Masha Operator HID — навык проекта

Используй этот навык для стендового HID-моста на HAKRCF405V2/STM32F405: подтверждён UART4→USB HID keyboard ввод на Raspberry Pi 4; отдельная версия с мышью остаётся экспериментальной. Общий план видеоклавиатурного моста находится в `docs/MASHA_OPERATOR_PLAN.md`.

## Источники истины

- Пакет, описание и проверенный клавиатурный HEX: `products/masha-operator-hid/`.
- Экспериментальный keyboard+mouse вариант: `products/masha-operator-hid/mouse/`; образ записан и проверен readback, но видимое движение/клики ещё не подтверждены.
- UART sender и исходные патчи: `products/masha-operator-hid/host/` и `products/masha-operator-hid/source/`.
- Локальная device-specific процедура может находиться в `firmware/HAKRCF405V2_keyboard/`; она исключена из Git, вместе с дампами и журналами.
- Дампы и оценки конкретной платы: `backups/flight-controller/`; каталог игнорируется Git и не должен попадать в публикацию.
- Перед действием проверь корневой `AGENTS.md`, `git status`, фактический USB-девайс и состояние платы. Не опирайся на старые `/dev/ttyUSB*`, DFU, питание или подключение к телефону.

## Зафиксированная конфигурация

- Betaflight 4.5.4 commit `25356b59a96dc975d777844f896b7c7855ea90e6`; config submodule `8057d261bb43a706764f73928b919af62666c247`.
- Цель `HAKRCF405V2`, STM32F405, UART4 TX=PA0/TX4, RX=PA1/RX4.
- YP-05/FT232RL на TTL 3,3 В: TXD→RX4, RXD→TX4, GND→GND; VCC не соединять.
- UART: 115200 8N1. Четырёхбайтовая команда `A5 modifier usage XOR`; допустимы только клавиатурные usage `0x04..0x38` и модификаторы Ctrl/Shift/Alt. HID press и release выдерживаются по 30 мс каждый; ACK отправляется после полного tap. `ARM` означает запрет команды при armed-состоянии.
- USB контроллера подключается к USB-host тестируемого устройства. Это прошивка полётника, не использовать для полёта; учитывать замену штатного Betaflight.
- Проверенный стендовый тракт: Pi 4 USB-host ↔ HAKRCF405V2 USB HID; ноутбук ↔ YP-05/FT232RL UART4; видеовыход Pi ↔ EasierCAP/AV-to-USB capture ↔ ноутбук. FT232 TXD→RX4 (PA1), RXD←TX4 (PA0), GND↔GND; UART 3,3 В, VCC не соединять. Перед подключением на новом стенде заново подтвердить распиновку и уровни.

## Порядок работы

1. Для чтения/описания сначала изучи `products/masha-operator-hid/README.md`, `SHA256SUMS`, хостовый скрипт и локальные патчи.
2. Перед сборкой используй чистый checkout двух закреплённых commit-ов. `source/apply_patch.sh` применяет клавиатурную версию; `mouse/source/apply_patch.sh` применяет полный экспериментальный keyboard+mouse набор. Скрипты проверяют версии и чистоту до изменений. Собирай `GCC_REQUIRED_VERSION=13.2.1 make -j2 CONFIG=HAKRCF405V2`; сборка сама по себе не подтверждает запись или runtime.
3. Для теста сначала заново идентифицируй serial-порт и физическое подключение. Для клавиатуры отправляй только одно явно запрошенное безвредное событие за раз; требуй UART ACK и свежий визуальный кадр. На Pi 4 владелец подтвердил видимый ввод тестовой строки в форме и ожидаемый отказ после отправки; не сохраняй строку или детали учётной записи.
4. Не угадывай реальные пароли и не делай повторных попыток входа. Одноразовое тестовое значение допустимо только по прямому запросу владельца, в его присутствии, на известном экране и без сохранения введённых данных.
5. Для мыши сначала проверь report descriptor с Report ID 1/2, затем на безопасном экране проверяй одно малое смещение/клик за раз; ACK не доказывает видимое движение. Текущая мышиная версия записана/readback пройден, но runtime-движение не подтверждено.
6. Отличай USB enumeration, успешную запись/readback, выход из DFU, UART ACK, реакцию целевого приложения и свежий видеокадр. Фиксируй только реально доказанные уровни.
7. Видеозахват и локальное отображение EasierCAP проверены вручную; кадровый тракт ещё не подключён к текущей сессии агента через MCP. Не называй агентскую интеграцию готовой.

## Границы безопасности

- Не выполняй запись Flash, erase, reset, изменение boot mode или подключение внешних сигналов без отдельного согласования непосредственно перед действием.
- Перед аппаратной записью повторно идентифицируй плату и чип, сними свежий полный дамп, проверь его хеш и конкретный HEX, затем прочитай Flash назад. Храни device-specific дампы только в игнорируемом `backups/flight-controller/`.
- Не посылай пароль, shell-команды, destructive shortcuts, макросы или длинный набор текста без отдельного запроса. Для демонстрации используй только явно разрешённое одноразовое тестовое значение и не сохраняй его.
- Полётный контроллер и его keyboard или keyboard+mouse build не предназначены для полёта. Предупреди о замене Betaflight и не допускай подключения моторов/пропеллеров при стендовом тесте.
- Не коммить дампы Flash, серийные идентификаторы, секреты и локальные логи с данными устройства.
