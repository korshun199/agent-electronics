# План проекта Masha Operator

**Цель:** подключить произвольное устройство с доступным видеовыходом и USB host к ноутбуку так, чтобы агент получал актуальное изображение экрана и мог посылать ограниченные события клавиатуры через отдельный USB HID-эмулятор. Сеть целевого устройства для работы не требуется.

## Схема

```text
Целевое устройство видео ─> видеоконвертер/UVC ───────────> ноутбук

Ноутбук/агент ─> USB-UART TTL 3,3 В ─> UART4 ─> HAKRCF405V2
Целевой USB host <────────────────────────── USB HID keyboard (мышь экспериментальная)
```

Видеоадаптер и HID-контроллер — разные части системы. Аналоговый вход выбирается под конкретный стандарт: CVBS, VGA, component и S-Video не взаимозаменяемы. Обычный USB host-порт ноутбука сам клавиатурой для цели не становится.

## Этапы реализации

### Этап 0. Инвентаризация и границы

- Зафиксировать ОС ноутбука, свободные USB-порты/хабы, имеющиеся HDMI/аналоговые конвертеры и маркировки.
- Для каждой целевой платы записать видеоразъём и стандарт, USB host-разъём, ожидаемую загрузочную/экранную процедуру.
- Выбрать HID-посредник, способный одновременно подключаться к целевому USB как клавиатура и принимать команды от ноутбука по отдельному serial/API каналу.
- Не покупать и не паять детали до подтверждения совместимости разъёмов, напряжения питания и режима USB.

**Выход:** таблица «есть / отсутствует / проверить», выбранный прототип и схема кабелей.

### Этап 1. Видео на ноутбуке

- Сначала подключить HDMI→UVC конвертер; аналоговый CVBS путь добавить отдельным профилем только если он нужен.
- Проверить перечисление камеры, список форматов, разрешение, цвет, FPS и задержку.
- Сделать утилиту/модуль захвата одного кадра с timestamp; проверить потерю сигнала и чёрный экран.

**Критерий:** агентский инструмент получает актуальное изображение с правильного источника, а не просто видит, что `/dev/videoN` появился.

### Этап 2. Клавиатурный канал на стенде

- Реализовать/выбрать HID-контроллер с USB HID выходом к целевому устройству и отдельным управляющим каналом к ноутбуку.
- Утвердить компактный протокол `tap/down/up/release_all`, ID запроса, ACK/NACK, timeout и watchdog.
- Проверить одну безвредную клавишу на тестовом компьютере; проверить отпускание клавиши при timeout/обрыве.
- Не вводить пароль и не запускать разрушительные комбинации.

**Критерий:** тестовый компьютер определяет USB keyboard, получает одну разрешённую клавишу, а отказ не оставляет клавишу зажатой.

### Этап 3. Локальный операторский процесс

- Написать сервис на ноутбуке с независимыми backend-ами захвата видео и serial/HID.
- Для Linux использовать V4L2/UVC и постоянное имя `/dev/serial/by-id/...`; предусмотреть отдельный backend для другой ОС.
- Ограничить агентский интерфейс методами `operator_status`, `capture_frame`, `key_tap`, `release_all`.
- Не предоставлять произвольное выполнение shell-команд, произвольный ввод текста, доступ к файлам ноутбука или сетевой порт без аутентификации.
- Маркировать кадры временем; при устаревшем/отсутствующем кадре блокировать клавиатурные действия.

**Критерий:** локальный сервис раздельно сообщает состояние видеопотока и HID-канала, а потеря видео блокирует ввод.

### Этап 4. Интеграция с агентом

- Подключить локальный сервис к Codex через MCP stdio либо другой поддерживаемый локальный tool-механизм.
- Проверить именно текущую сессию: агент должен получать кадр и вызывать ограниченный HID tool. Доступность сервиса только из терминала не подтверждает интеграцию.
- Оставить подтверждение пользователя для постоянных изменений, записи устройств, прошивки, учётных записей, сетевых настроек и действий с данными.

**Критерий:** видимый end-to-end путь в журнале: кадр с timestamp -> команда с ID -> ACK от контроллера -> наблюдаемое изменение экрана.

### Этап 5. Надёжность и эксплуатация

- Проверить 100 последовательных кадров, латентность, зависание и восстановление видеоустройства.
- Проверить повтор команды, тайм-аут, потерю serial, перезапуск контроллера и безопасное `release_all`.
- Добавить цветной статус: ВИДЕО OK/STALE/OFFLINE, HID OK/OFFLINE, последний кадр, ACK/ошибка.
- По умолчанию не хранить кадры и не записывать содержимое клавиатурного ввода; при необходимости диагностической записи сохранять только по отдельному включению и локально.

## Решения, требующие инвентаризации перед покупкой/разработкой

| Узел | Варианты | Что подтвердить |
| --- | --- | --- |
| Видео | HDMI→UVC; CVBS→UVC | разъём источника, стандарт сигнала, режимы захвата и задержка |
| HID эмулятор | готовый KVM; MCU HID с отдельным UART/USB control | одновременная работа host-эмуляции и управляющего канала |
| Связь агент—ноутбук | MCP stdio или локальный разрешённый bridge | доступность локального инструмента из используемой Codex-сессии |
| Питание | от ноутбука/отдельный блок | требования capture/KVM и риск обратного питания целевой платы |

## Ограничения

- Это удалённые глаза и клавиатура, а не обход аутентификации или восстановления пароля.
- Кадр может быть старым, чёрным из-за неподдержанного режима/HDCP или скрывать вывод, если целевое устройство не выдаёт видео.
- HID ACK означает лишь, что контроллер принял команду; реакцию цели подтверждает только свежий кадр.
- Переход к работе с конкретной платой начинается после идентификации её разъёмов и электрических требований.

## Статус на 2026-11-26

- На стенде HAKRCF405V2/STM32F405 принимает UART4-команды и работает как USB HID keyboard. Между ноутбуком и платой использован YP-05/FT232RL: TXD→RX4 (PA1), RXD←TX4 (PA0), общий GND, VCC не подключён. Целевым USB-host в последней проверке был Raspberry Pi 4.
- В правильной физической схеме UART ACK сопровождался видимым вводом в экранную форму Pi; после отправки формы свежий кадр показал отказ входа. Это проверяет реальный тракт клавиатуры и Enter на указанном стенде, но не логин и не универсальную совместимость.
- Видеовыход Pi захватывался локально через EasierCAP/AV-to-USB2.0 как UVC/MJPEG 720×480@25 fps. Кадр отображался отдельно на ноутбуке; имена `/dev/videoN` меняются, часть кадров имела MJPEG-артефакты. Инструмент захвата в текущей сессии агента и MCP-сервис не реализованы.
- Экспериментальная мышиная версия собрана, записана и полностью проверена readback; USB HID descriptor с отдельными ID клавиатуры и мыши наблюдался. Движение курсора и клики на цели не подтверждены и не заявляются как готовая функция.
- Каталог, воспроизводимые патчи, HEX, SHA-256 и проектный навык находятся в [`products/masha-operator-hid/`](../products/masha-operator-hid/README.md) и [`.agent/skills/masha-operator-hid/SKILL.md`](../.agent/skills/masha-operator-hid/SKILL.md). Device-specific дамп, журнал прошивки и пользовательские кадры не публикуются.

Итог v1: видеонаблюдение на ноутбуке и клавиатурное управление Raspberry Pi стендово подтверждены. Для полной агентской операторской системы остаются интеграция свежих кадров с инструментом агента, блокировка ввода при устаревшем видео, безопасное восстановление после потери связи, а также runtime-проверка мыши. Не использовать реальные пароли и не выполнять destructive-комбинации.
